Security

The following requirements apply to this repository and associated technology projects:

- Never commit passwords, API keys, access tokens, or other secrets.
- Use secure secret-management mechanisms for credentials.
- Follow least-privilege access principles.
- Protect customer, employee, and company information.
- Do not bypass security controls.
- Do not weaken repository permissions to solve an unrelated integration problem.
- Document significant security or architecture changes.
- Do not claim successful execution without verifiable evidence.

Repository access does not automatically prove that an external GitHub integration has write authorization.

1. Properly authenticated.
2. Properly installed or connected.
3. Authorized for the required repository.
4. Granted only the permissions necessary for its approved function.
5. Verified through an actual controlled transaction.

Change Management

Significant repository changes should follow this process:

1. Identify the objective.
2. Inspect the existing implementation.
3. Determine dependencies and risks.
4. Make the smallest appropriate change.
5. Validate the change.
6. Record evidence.
7. Report the result.
8. Obtain required approval before production-impacting implementation.

AI & Automation Standards
