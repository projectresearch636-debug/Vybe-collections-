# Change Management Policy

## Purpose

Ensure technology changes are controlled, traceable, and aligned with business objectives.

## Required Process

1. Define the objective.
2. Inspect the current implementation.
3. Identify dependencies.
4. Assess risks.
5. Implement the smallest suitable change.
6. Validate the change.
7. Record evidence.
8. Report the outcome.
9. Obtain required approval where necessary.

## Repository Changes

- Do not modify unrelated files.
- Do not overwrite existing files without justification.
- Use dedicated branches for significant changes.
- Changes to protected or production branches require appropriate approval.
- Pull requests should document scope, rationale, validation, and risks.

## Emergency Changes

Emergency changes must still be documented and reviewed retrospectively.

## Evidence

No change may be reported as successfully implemented without evidence of execution.
